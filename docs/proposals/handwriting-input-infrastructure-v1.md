# 手写输入基础设施开发提案 v1

状态：P0/P0.1、P1、P2、P3 及 P3.1（含 P3.1.1 设置后书写衔接与写入权状态处理）已实现并经用户回归确认。P3.2 免证书便捷连接暂缓，后续优先推进系统级删除语义与 Mathscape 核心工作流。未落地的类型、表名和接口名仍是候选契约。

手稿在 Mathscape 笔记体系中的命名、关联、地图位置和回收站方案见 [手稿融入 Mathscape 笔记本提案 v1](ink-notebook-integration-v1.md)。

## 1. 目标与首个验收场景

为 Mathscape 建立可复用的手写输入底座：采集笔迹、保留编辑历史、可靠保存与恢复，并把指定时刻的手稿冻结为可引用的来源证据。桌面数位板、局域网平板浏览器和未来 Android 原生采集端使用同一套 Ink 契约。

首个完整验收场景是：用户从一道已有习题开启书写会话，在 Samsung Tab S8+ 上写推导，期间网络中断，恢复连接后完成同步；用户保存一个快照，退出并重启桌面应用，仍能找到该手稿、打开当时的内容，并准确定位到选定的笔迹。随后继续书写、擦除或撤销，不改变已经保存的快照与来源定位。

Ink v0 的完成条件是这个闭环可靠成立。模型分析和数学语义晋升以此为输入基础，另行开发。

## 2. 设计依据与现有边界

工程事实以[架构](../architecture.md)、[数据模型](../data-model.md)、[存储与集成](../storage-and-integrations.md)和当前代码为准；数学来源与晋升边界参考 EMIR 设计规范（未入库）。手写输入调研（未入库）提供生态与交互候选，不作为实现完成度或设备能力的保证。

已有能力可复用：

- Rust 领域层、SQLite 存储、Tauri 命令与 TS 前端之间的职责划分；
- Artifact Pool 的不可变字节、内容寻址、完整性检查与受限读取；
- StableId、RevisionId、来源对象、MapPatch 及登记事务；
- 来源材料阅读、查询与只读图投影。

本次开发需要补足的接口：

- 当前没有统一的 Ink 会话、笔迹操作与可靠同步契约；
- 当前 `SourceSpan` 接受 PDF/Markdown 定位，尚不能直接表达 Ink 定位；
- 阅读与来源详情需要增加 Ink 快照和选区的打开能力；
- 当前 LLM 消息契约没有图片输入。本提案保留分析输入边界，不把多模态调用列入 Ink v0。

保存手稿不要求已有完整书目、DialectScope、共享语义或 Lean 证书。Ink 来源定位也不应通过生成 Markdown 或 PDF 来绕过。

## 3. 本次交付范围

### 3.1 Ink v0 必须交付

1. 有限页面上的普通笔书写、整笔擦除、撤销重做、缩放与平移；
2. 保存采集端报告的样本、笔刷描述和编辑操作，保留取消与中断状态；
3. 桌面本地采集与会话列表、重开、继续书写；
4. 单写入者的 LAN InkPad、二维码配对、写入确认与断线续传；
5. 自动保存、已确认数据的进程崩溃恢复、客户端未确认队列恢复；
6. 后端生成的不可变 Ink 快照，通过 Artifact Pool 管理；
7. 快照上的整笔选区、Ink locator、SourceSpan 登记和来源回链；
8. 协议、持久化、旧数据迁移与真实设备验收材料。

### 3.2 后续扩展

本次不实施：多写入者协作、CRDT、云同步、完整 Android Mathscape、移动端原生变换、复杂笔刷、无限画布、OCR/HMER、自动来源单元切分、共享语义对齐、ProofState 或 Lean 工作流。桌面 Ink Lab 已实现有限页面、套索变换和局部擦除的 P0 版本。

Android 原生输入是由设备实验触发的扩展分支。若 Web 输入达不到基本书写要求，可提前验证原生采集，但仍遵循同一 Ink 契约，不同时扩展完整移动产品。

临时草稿与废稿的删除需求和必要约束见 §7.5。本提案记录这些需求；完整删除模型及实现依赖后续系统级对象生命周期设计，在手稿主体功能完成后，与其他 Artifact、来源层/语义层图对象及历史修订统一考虑，不作为当前 P2/P3 的新增交付条件。

## 4. 核心语义与不变量

### 4.1 观察记录与数学解释分开

Ink 保存用户输入和编辑的可观察事实。笔迹顺序、停顿、擦除、圈画和修改能支持后续解释，但不能直接等同于用户的推理状态。一笔不等于一个公式，一次停顿不等于一个证明步骤，撤销也不自动表示放弃一种证明路线。

底层使用 Ink 编辑历史或 `InkTrace`。未来模型提出的转写、思路、证明步骤和分支属于解释候选，引用固定快照和选区，并保留不确定性。输入质量、解析质量、数学正确性与人工接受分别记录。

### 4.2 会话、文档、历史与快照分开

| 对象 | 职责 | 身份与变化 |
| --- | --- | --- |
| `InkDocument` | 页、笔迹及当前可编辑内容 | 稳定 document_id；当前状态由有序历史派生 |
| `InkSession` | 一次书写活动、设备与关联材料 | 稳定 session_id；可以继续已有文档 |
| `InkOperation` | 笔迹、页面与可见性操作 | 唯一 operation_id；只追加，不改写旧操作 |
| `InkStroke` | 一次采集产生的样本序列与笔刷 | 稳定 stroke_id；完成状态显式记录 |
| `InkSnapshot` | 固定历史前缀及其内容 | snapshot_id 与受管 Artifact；内容不可变 |
| `InkSelection` | 固定快照中的选定证据 | 绑定快照及明确笔迹集合 |

连接断开不等于会话结束；会话结束不等于文档封存。历史顺序由后端文档序号决定，不依赖不同设备的墙上时钟。

### 4.3 必须保持的不变量

- 已持久确认的操作在支持的进程崩溃恢复场景下不丢失；未确认操作不得显示为已在桌面持久化。
- 同一操作的相同内容重试返回原回执；不同内容复用同一标识必须冲突。
- 擦除与撤销改变可见状态，不物理删除原始样本或旧历史。
- 快照绑定确切的历史前缀；后续编辑不能改变快照字节、笔迹集合或旧 locator。
- 所有来源定位具有可验证锚点；不能把 Ink 页号填入 PDF 页号字段。
- 缺少压感、倾角或上下文时保留缺失或未知状态，不补造能力和数学环境。
- 预测点只用于临时渲染，不写入实际采集证据。
- 前端和远程客户端不拥有来源登记权限；后端重新绑定受管输入并执行验证。

## 5. 架构与模块落点

```text
Desktop Pointer Adapter          Browser InkPad          Android Adapter（后续）
          │                            │                         │
          └──────────── Canonical Ink DTO / Operations ───────────┘
                         │                    │
                    即时本地渲染         客户端未确认队列
                                              │
                                   Tauri IPC / Ink transport
                                              │
                                      Ink Application Service
                                              │
                              验证 → 有序持久化 → Durable ACK
                                              │
                                     固定历史前缀 / 快照
                                              │
                                        Artifact Pool
                                              │
                              Ink Reader / Locator / SourceSpan
```

候选落点如下；新增独立 crate 以形成长期模块边界为条件，不为原型机械拆包。

| 模块 | 工作 |
| --- | --- |
| `mathscape-domain` 的 Ink 模块 | 值类型、操作 DTO、快照、locator 与确定性不变量；不依赖 UI/数据库 |
| `mathscape-store-sqlite` | 会话、操作、回执、写入者 epoch 和快照引用的事务存储 |
| `mathscape-artifact` | 复用受管字节导入与读取，不增加第二套 Ink 对象池 |
| `mathscape-orchestrator` 的 Ink 模块 | 输入重绑定、快照构建、定位验证与来源登记计划 |
| `apps/mathscape-desktop` | 统一应用服务、Tauri 命令、LAN 服务生命周期与事件 |
| `frontend/src/ink/`（新增） | 采集、即时投影、渲染、队列、会话入口与快照阅读 |
| `mathscape-query` / `mathscape-graph` | 新定位的只读回链和投影；不承载书写工作状态 |

TS 需要即时投影以保持笔尖反馈；Rust 负责权威验证和提交。两端使用同一版本化操作语义和 golden fixtures，不各自定义一套文档规则。领域契约由 Rust DTO 及 Schema 驱动，前端类型的生成方式在 P0 确定。

桌面 IPC 与 LAN 请求经过同一应用服务。网络层只做会话认证、消息边界和传输，不另写一套笔迹存储或来源登记逻辑。

## 6. Ink 数据契约

### 6.1 采样、坐标与能力

`InkPoint` 至少表达页坐标 x/y、采集片段内相对时间，以及可选 pressure、tilt 和设备报告的相关属性。字段单位、精度、范围和缺失语义必须写入版本化契约。

坐标使用固定页面坐标系，原点、轴方向和页面尺寸明确。viewport、缩放比例、devicePixelRatio 和屏幕方向属于采集或显示变换，不改变已经保存的页坐标。第一版页面尺寸创建后固定，新增页使用稳定 page_id，显示页码只是可变阅读顺序的标签。

采集适配器记录实际运行环境、设备类别与能力状态。API 字段存在或值为零不表示硬件支持对应传感器；能力可以为 unknown。归一化方式与数值精度由 P0 fixture 验证，Schema 冻结后才能进入 P1 持久化。

必须保存用于重建笔迹的样本序列。平滑轮廓、降采样预览、Canvas 路径与预测点不替换这些样本。处理 coalesced events 时避免重复加入父事件；同时使用 rawupdate 与 move 时也必须避免重复采样。

一个 `capture_segment_id` 表示连续采集时钟片段。页面刷新、进程重启后生成新片段，不能把新的相对时间接成旧采集时钟；文档操作序号继续保持顺序。

### 6.2 操作与用户命令

候选操作类别：

```text
page.add
stroke.begin
stroke.append_samples
stroke.finish       // completed | cancelled | interrupted
stroke.set_visibility
history.undo
history.redo
```

一笔书写是一个用户 command，可包含多个有界样本批次。整笔擦除是一个独立 command；撤销重做针对用户 command，而非每个采样批次。

每次撤销或重做也追加历史，后端根据明确目标 command 和保存的前态执行。第一版只撤销已经完成的命令；活动笔迹先完成或取消。`stroke.begin/append/finish` 必须构成合法状态机，终结后不得继续向原 stroke_id 加点。

样本不能逐点跨 Tauri 或逐点同步 SQLite。使用有界批次；批次大小和最大缓存时间在 P0 测量后固定，并覆盖抬笔、取消和关闭时的尾批次。

### 6.3 关联材料

`InkContextRef` 保存关联对象、角色、来源范围及所依据的 revision。例如 primary_problem、reference_material；允许没有关联的自由草稿。新关联追加修订或操作，不静默覆盖旧会话的语境。

会话上下文仅说明用户当时关联了哪些材料。它不自动构造 DialectScope、RepresentationBinding 或 ProofContext，也不自动建立 `proves` 等来源关系。旧材料已退役时仍应解析历史引用，并显示其当前状态；不能悄悄换成当前 revision。

### 6.4 快照与选区

候选快照 manifest：

```text
schema_version
document_id / originating_session_id
through_document_seq
parent_snapshot_id（可选）
page specifications
capture segments / brush specifications
ordered operations and samples through the frontier
context references at the frontier
materialized visible state fingerprint
```

v0 优先使用自包含快照，包含重建该历史前缀所需的数据，方便重开与搬迁。manifest 与可见状态摘要必须可由后端重算；确定性序列化规则固定，内容哈希以实际受管字节为准。后续若改为分块 manifest，新版本必须显式引用全部不可变依赖。

整笔选区保存快照 Artifact、page_id 和去重后的 stroke_ids。框选或套索手势转换成显式笔迹集合，规则固定并记录；第一版不承诺笔迹内部样本级裁切。跨页选择拆成多个定位。

普通选区只选择快照中可见的笔迹；查看已擦除内容须显式进入历史视图并绑定对应历史位置。不能用最终可见图像解释用户此前看到的全部状态。

## 7. 持久化、恢复与快照提交

### 7.1 权威存储

SQLite 保存会话元数据、操作顺序、幂等回执、写入者状态与快照引用。小型操作及有界的小样本批次可直接保存为版本化 DTO；大批次使用不可变 payload Artifact，SQLite 保存引用。两种承载方式采用相同的样本验证和操作指纹规则，阈值在 P0 测量后确定，避免每个采样批次都产生一个小文件。不能把持续增长的全部笔迹放进一个可变 SQLite BLOB 或另一个未纳入 Workspace 的文件。

候选逻辑表为 ink_documents、ink_sessions、ink_operations、ink_writer_state、ink_snapshots、ink_requests。它们保存写入事实；可重建投影不是第二套权威数据。快照来源与 catalog 仍复用现有 Artifact 结构，不把每笔 stroke 都创建成地图节点。

客户端先把待提交批次写入本地 outbox，再允许该批次显示为“本机已保存”。浏览器使用 IndexedDB，需检测可用性与写入失败；本机保存失败时明确展示，不宣称能在刷新后恢复。桌面本地入口采用相同提交语义，避免绕过验证。

### 7.2 操作提交与确认

后端处理持久操作的顺序：

1. 检查消息上限、Schema、样本数值、状态机和会话授权；
2. 如需 payload Artifact，先通过现有 staging/提升路径登记不可变字节；
3. 在一次写事务中检查写入 epoch、顺序与幂等，登记操作、更新 head、写入回执；
4. 事务成功后发送 durable ACK；客户端收到后才移除对应 outbox 项。

服务端收到消息、转发预览或尚未提交的投影都不是 durable ACK。重复请求先核验原请求指纹并返回原成功回执，不被后来变化的 head 错误拒绝。payload 登记后业务事务失败可留下未引用 Artifact，但不得出现成功操作引用缺失字节；重试复用内容。

浏览器关闭前的网络 flush 是尽力而为，不能作为耐久保证。尚未送到客户端 outbox 的尾部样本也不能承诺恢复；该损失窗口由有界批次控制，并在设备实验中记录。

### 7.3 中断恢复

后端重开以操作历史和已提交 head 为准，重新验证序号、引用、哈希及投影指纹。未终结笔迹显示为待恢复；启动时不立即追加 interrupted 终结，因为原客户端 outbox 可能仍有合法的后续样本和 finish。先核对原写入者的恢复队列，无法继续的笔迹再通过幂等操作标记 interrupted；不能补造缺少的末端点或把 interrupted 自动标成 completed。

客户端恢复 outbox 后，先核对服务端最后确认序号，再按原顺序提交。已撤销的写入权限或旧 epoch 队列必须保留并显示冲突；不得自动重编号并写进当前文档。用户可将其导入独立恢复草稿，这应是显式、可审计的操作。

本提案承诺已确认数据的受支持进程崩溃恢复。文件系统损坏、存储介质失效与浏览器数据清理属于可诊断的材料缺失，不能以网络重试掩盖。延续现有 Workspace 备份与完整性边界。

### 7.4 快照创建

用户“保存快照”携带 request_id 和预期文档 head。客户端先完成活动笔迹并同步待提交操作；仍有 pending 或冲突时不能把快照展示成包含这些内容。允许对明确显示的服务端已保存前缀生成快照，但必须说明其范围。

快照创建流程：

1. 后端在短事务中校验预期 head，固定 through_document_seq，并持久保存幂等请求绑定；
2. 验证该前缀的完整历史与 Artifact，构建确定性 manifest；
3. 通过 Artifact Pool 导入快照字节；
4. 在事务中完成快照引用和回执登记；
5. 返回快照 Artifact 和来源阅读入口。

后续书写可以继续追加，不影响步骤 1 固定的前缀。跨文件与数据库步骤不宣称全局原子；未知结果重试必须恢复同一请求所绑定的前缀，不能改用更新后的 head。失败快照不能显示为成功。

PNG/SVG 不是必需权威存储。v0 从受管快照重建阅读画面；若保存预览，则作为独立派生产物，记录输入快照、渲染器版本、笔刷配置和坐标映射。高级笔刷的跨平台像素一致性另行验证。

### 7.5 临时草稿、删除需求与生命周期约束（待全局设计）

用户可以只把手稿当作临时计算纸，需要主动清理草稿和废稿。自动保存用于防止意外丢失，不代表用户要求永久留存，也不自动生成快照或登记来源证据。当前新建手稿及编辑历史保存到 SQLite；显式“保存快照”才生成受管 Artifact。当前实现尚无完整的手稿删除入口。

后续实现应支持用户主动丢弃草稿，并清楚表达操作范围。是否采用回收站、归档或其他可恢复流程，由系统级删除提案统一决定。本阶段保留以下约束：

- **区分操作对象与意图**：从列表移除、删除当前文档及其会话/操作历史、删除历史快照、解除关联，以及删除来源/语义对象是不同操作；不能用一个含糊的“删除”入口默默执行全部动作。
- **保护已有引用**：删除当前手稿不能隐式级联破坏被 SourceSpan、历史修订或后续分析记录引用的快照与定位。被引用内容的保留、退役或显式清除规则交由全局模型定义；仍存续的引用必须可解析，不能静默指向其他快照或当前内容。
- **区分不可变与留存**：不可变约束禁止覆盖快照字节或改写已引用的历史前缀，不要求所有数据永久保存。允许在统一授权、引用检查和留存规则下清除数据；当前的追加历史约束针对编辑操作，不禁止未来明确授权的对象删除。
- **协调未确认写入与恢复**：删除流程需明确活动笔迹、未确认 outbox、远端会话和恢复队列的处置。延迟重试或重连不能自动重建已删除的文档；也不能在未明确处置范围时静默丢弃未确认内容。
- **保留稳定身份和明确依赖**：文档、会话、快照、Artifact 和来源定位继续使用稳定身份与显式引用。文档删除不应依赖界面标题、页码或文件路径猜测关联范围；不在当前开发中引入自动级联清除。

实施顺序是先完成 P2 来源登记与回链、P3 跨设备书写闭环，再单独设计并实现系统级删除语义。全局设计统一确定界面移除、归档、退役、解除引用与物理删除的含义，以及回收站期限、级联策略、历史记录解析和 Artifact 垃圾回收规则；本节不提前固定表结构或删除算法。

## 8. LAN 协议与单写入者

### 8.1 通道职责

采用 Axum + WebSocket、二维码配对和版本化 JSON。二进制编码、mDNS 和 CRDT 留待性能与产品需求明确后决定。

通道区分 preview 与 durable operation。preview 可丢弃，只用于桌面实时观察；durable operation 必须有序、幂等并得到持久确认。书写端始终本地渲染，不等待服务端往返。

概念消息：

```text
hello / resume
session.context
preview.stroke
operation.submit
operation.ack
operation.conflict
snapshot.request / snapshot.receipt
session.closed
```

持久操作信封至少包含 protocol_version、document_id、session_id、writer_epoch、operation_id、client_seq、previous_operation_id 和 payload。握手绑定文档 head；随后使用连续序号和前驱标识验证链，保证离线排队不依赖逐条取得服务端新序号。

消息大小、单批样本数、队列容量和单会话总量设定显式上限。超限返回诊断或背压，不静默截断样本。

### 8.2 单写入者与重连

同一文档只允许一个活动写入者；桌面镜像为观察端。申请切换到桌面书写时，先同步或保留旧端 pending，再显式转移写入权并生成新 epoch。断开连接本身不立即转移权限。

同 epoch、相同 operation_id 与内容重试返回原 ACK；客户端序号有缺口时要求补齐；前驱不符、同标识不同内容或旧 epoch 写入返回冲突。重连凭据与文档租约分别校验，不能仅凭 session_id 取得写权限。

应用重启后的恢复认证和租约状态属于 P3 必须验证的协议情形。新的配对不能静默接收旧端尚未确认的历史；服务端应区分原写入者恢复与新的写入者接管。

### 8.3 配对与能力限制

LAN 服务由用户开启，关闭会话或服务后撤销相应凭据。二维码使用短期、单次配对凭据，成功后换取限制到当前会话的连接凭据；日志不记录完整凭据。

只暴露 InkPad 静态资源、当前会话明确授权的上下文和 Ink 操作，不开放任意文件读取、完整 Workspace 查询或通用 Tauri 命令。校验 WebSocket Origin 与会话凭据，设定超时和资源上限；Origin 不能替代认证。

P0 可在可信局域网使用 HTTP 验证，但必须记录 secure-context 能力限制。正式使用方案在 P3 明确：浏览器路径采用设备信任的 HTTPS/WSS，或使用具有受保护传输的 Companion。不能将自签名证书未经设备信任的连接宣称为已解决安全上下文。若 TLS 信任与离线队列在目标设备上无法可靠成立，LAN Browser 仍属实验能力，不标记正式验收完成。

## 9. Ink 定位与 EMIR 来源接入

### 9.1 新定位类型

在 SourceSpan 中新增可独立成立的 Ink locator，保留旧 PDF/Markdown payload 的兼容读取。候选字段：

```text
InkLocator
  snapshot_artifact_id
  page_id
  stroke_ids
  selection_mode       // whole_strokes in v0
```

Ink locator 必须验证快照媒体类型、Schema、实际内容哈希、page_id、stroke_ids 和选择模式。证据显示 bbox 可由笔迹及笔刷几何派生；bbox 不是唯一稳定身份。用户框选矩形不能替代被选中的具体笔迹集合。

新 locator 自身足以让 SourceSpan 可定位。page/block/inline 的既有规则不能未经解释直接套到 Ink；P0 fixture 确定新增粒度或类型分支，并同步到序列化、构造器、存储验证、query 和 reader。不得为 Ink 构造空壳 PDF PageCoordinate。

### 9.2 保存与登记状态

必须区分：

```text
本机 outbox 已保存
→ 桌面操作已持久确认
→ 不可变快照已登记到 Artifact Pool
→ 用户指定选区已登记为来源证据
```

这些状态分别有成功条件。保存快照不自动接受数学解释，也不自动登记 SourceSemanticUnit。

v0 提供“登记此选区为来源证据”：后端从受管快照重建选择、构造 SourceSpan 与受控登记计划，按 request_id、预期快照身份和选择指纹原子提交地图对象与回执。来源登记失败不影响已经保存的手稿；重试不能重复生成不同证据对象。

这个用户指定的定位入口不伪造 discovery run，也不绕过现有地图对象不变量。可以共享底层事务和 MapPatch 验证，但需要独立的业务请求和授权边界。SourceSpan 的稳定身份基于固定快照和规范化选择，不能按显示页码或 bbox 猜测。

### 9.3 来源阅读与后续晋升

点击 Ink Artifact 或 SourceSpan 打开对应快照，显示选定笔迹，允许返回相关习题与书写会话。快照阅读为只读；“继续书写”打开当前文档并明确区分当前内容与历史快照。

材料图可展示快照 Artifact，证据模式展示 SourceSpan。高频采样、连接状态和未确认草稿不进入来源图。后续从手稿提取来源单元时，继续遵循候选、验证、用户接受与登记的边界；未完成的尝试不因用户写下或保存而获得已证明状态。

## 10. 前端交互

提供两个会话入口：从已有来源单元“开始手写”，以及独立“新建手稿”。会话列表显示最近文档、关联材料、最后持久保存时间及 pending 状态，重启后仍能找到。

书写页显示关联题目或材料摘要、有限页面、笔工具、整笔擦除、撤销重做、缩放平移、保存快照与连接状态。默认以笔书写、触摸导航；掌触和笔触并发策略在目标设备实测，不能把 Pointer Events 支持等同于已实现掌拒。

状态使用用户可理解的表述：本机已保存、等待桌面同步、桌面已保存、连接中断、同步冲突、快照已保存。关闭或切换时仍有 pending，应展示数量和恢复入口，不能用无条件“完成”按钮抹去未确认数据。

框选或套索首先选择整笔；可预览实际选中笔迹，再登记来源证据。未来“询问 Mathscape”使用固定快照与选区，另由多模态提案定义，不在 v0 接入按钮占位或自动发起模型请求。

## 11. 交互与渲染优化方案

本节记录 P0 实机验收后确认的优化方向。它们属于 Ink Lab 的 P0.1 交互优化阶段；不可变快照、EMIR Ink locator 和来源登记仍按 P2 实施。

### 11.1 当前问题与目标

当前原型把笔迹、套索框、变换控制点和擦除预览放在同一个 Canvas 状态中，导致工具切换后残留选择框、控制点没有独立命中区域、变换过程中缺少稳定的实时预览，局部擦除还会重复扫描大量采样点。

P0.1 的目标是：

- 工具切换、页面切换和手势结束时清理所有临时选择与预览状态；
- 为套索框、四角缩放点、旋转点、拖动区域和局部擦除器提供独立命中区域与光标；
- 变换过程只更新临时矩阵和预览层，抬笔时才追加一个 `transform` 操作；
- 局部擦除过程显示擦除光标和受影响片段的实时预览，抬笔时才追加 `partial_erase`；
- 变换、擦除和页面操作继续使用 Mathscape 自己的 InkOperation，不让渲染库的对象 JSON 成为权威数据。

### 11.2 状态和渲染层分离

前端把状态分为四类：

```text
ToolState       pen | select | erase | partial_erase
SelectionState  selected_stroke_ids | lasso_path | handles
GestureState    idle | writing | lasso | dragging | scaling | rotating | erasing
PreviewState    transform_matrix | erase_path | preview_fragments
```

渲染划分为四层：

```text
SettledInkLayer       已完成笔迹
ActiveStrokeLayer     当前正在书写的笔迹
SelectionOverlay      套索、边框、控制点和光标
PreviewLayer           变换与局部擦除的临时结果
```

切换工具必须执行统一的 `resetTransientInteraction()`：终结或取消当前手势、清除套索路径、清除变换矩阵、清除擦除预览和释放指针捕获。选择状态可以保留，但选择框只在 `ToolState = select` 时显示；切换到笔或擦除时隐藏 Overlay。

选择框的命中优先级固定为：旋转点 → 四角缩放点 → 框内拖动区域 → 已选笔迹 → 空白区域套索。每个命中区域返回语义工具和 CSS cursor，例如 `grab`、`grabbing`、`nwse-resize`、`nesw-resize`、`crosshair` 和 `cell`。Android 触控不依赖鼠标 hover，触碰控制点时显示短暂的控制状态和预览变化。

### 11.3 渲染适配器路线

保留 `InkDocument`、`InkStroke`、`InkOperation` 和当前的 `perfect-freehand` 输入样本格式，把画布交互改为可替换的渲染适配器：

```text
InkDocument / InkOperation
          ↓
InkViewAdapter
          ├── settled stroke nodes
          ├── selection / Transformer
          ├── active stroke preview
          └── eraser preview
```


Konva 节点只保存 `stroke_id`、当前显示几何和临时变换，不保存 Mathscape 的完整来源数据。`transform` 提交时把矩阵写入 InkOperation；取消手势只丢弃 PreviewState，不能产生空操作。

Fabric.js 作为局部擦除算法的对照实现。其官方 EraserBrush 示例支持擦除笔刷、可擦除对象和擦除撤销，[EraserBrush 文档](https://fabric5.fabricjs.com/erasing)可用于评估交互差异。即使采用 Fabric，也只把它当作渲染适配器，不能直接采用 Fabric JSON 作为 Ink 文档。

tldraw 暂不作为基础依赖。其 SDK 的生产使用需要 trial、hobby 或 commercial license 和有效 license key，[官方许可说明](https://tldraw.dev/community/license)与 Mathscape 的本地优先基础设施目标不匹配。Excalidraw 继续作为交互参考，但其公开 issue 中仍有整笔擦除与局部擦除语义的限制报告，[issue #9199](https://github.com/excalidraw/excalidraw/issues/9199)，需要单独验证后才能复用。

### 11.4 局部擦除算法和性能

当前的局部擦除会在移动事件中重复比较所有笔迹的采样点。P0.1 改为：

1. 每个可见笔迹缓存页面坐标 bounding box；
2. 使用均匀网格或 R-tree 找到与擦除路径相交的候选笔迹；
3. 只有候选笔迹进入局部几何计算；
4. 擦除过程中只更新候选笔迹的 PreviewLayer，不重建整页；
5. 抬笔时把受影响笔迹切成有序片段，追加一个 `partial_erase` 操作；
6. 原始 stroke 和原始采样继续保留，撤销通过恢复 source stroke 实现；
7. 片段 ID、采样顺序、page_id 和 capture_segment_id 必须可确定性重建。

局部擦除器使用屏幕半径映射到页面坐标，显示圆形擦除光标。笔迹密度高时采用采样分桶和线段距离检查，不在每个移动事件中调用完整渲染器。静态完成笔迹缓存轮廓几何；变换只修改节点矩阵，不能因为拖动每帧重新生成所有 `perfect-freehand` 轮廓。

P0.1 以真实 Tab S8+ 样本收敛性能阈值，至少记录：输入事件到 Overlay 更新的延迟、局部擦除时的帧时间、受影响笔迹数、采样点数、页面总笔迹数和内存。验收要求是变换预览和擦除光标连续跟手，局部擦除不因页面中存在大量无关笔迹而出现明显额外延迟；具体数值写入设备报告后冻结。

### 11.5 P0.1 开发步骤

1. **状态清理**：已实现工具切换、页面切换、取消和 `pointercancel` 的统一状态复位；已补充选择框残留回归。
2. **交互命中层**：已建立控制点和擦除光标的命中区域、光标状态、触控反馈及选择层测试。
3. **实时预览**：已将变换和局部擦除放入独立 PreviewLayer；已验证拖动、四角缩放、旋转、取消和抬笔提交的一致性。
4. **Konva 适配器实验**：在独立分支或可切换实现中比较当前 Canvas 与 Konva 的帧时间、控制点命中和 S Pen 触控表现。迁移只覆盖 ViewAdapter，不改变 Ink JSON。
5. **局部几何优化**：已加入页面均匀网格、候选笔迹过滤、片段切分预览和 PreviewLayer 增量重绘；5 分钟和 20 分钟真实手稿回放测量待实机执行。
6. **多页交互完善**：页面缩略条、添加/切换页面、当前页选择状态和导出/导入回归；页面结构操作与笔迹操作保持可区分。

### 11.6 P0.1 验收标准

- 切换到笔、整笔擦除或局部擦除后，选择框、套索路径和变换控制点立即隐藏；
- 旋转点、四角缩放点、框内拖动区和擦除路径具有正确命中区域与光标；
- 拖动、缩放和旋转过程中每一帧显示临时结果；取消手势不产生操作，完成手势只产生一个 `transform`；
- 局部擦除过程中圆形光标和片段预览跟随笔尖，完成后产生可回放、可撤销的 `partial_erase`；
- 页面新增、页面切换、导出和导入保持 page_id、笔迹归属和历史顺序；
- 原始采样、pressure、tilt、时间和 source stroke 在变换与局部擦除后仍可读取；
- 使用真实 Tab S8+ / S Pen 回放至少一份短手稿和一份 20 分钟手稿，记录性能数据和未解决问题；
- 所有 P0.1 浏览器测试、Ink 契约测试和既有 P0 回归通过。

### P1 本地会话与可靠保存

### P3 LAN InkPad 与端到端验收

接入受限 Axum 服务、独立 InkPad 页面、WebSocket、配对与单写入者协议。实现预览/持久通道、背压、断线重连、桌面重启认证恢复和写入权转移冲突处理。

在真实 Tab S8+ 完成首个验收场景，并解决受保护传输、客户端持久化与 Web API 能力差异。桌面本地入口与远程入口对相同操作 fixture 生成相同的数学书写内容与选择结果；仅在采集和会话元数据也相同时要求快照字节一致，真实设备的来源元数据不得为追求相同哈希而被删除。

P3 软件实现已落地，使用说明见 [InkPad](../../frontend/ink-pad/README.md)。正式入口是 Mathscape 手稿页的“平板书写”，无需再启动 P0 的 Node 接收后台。

1. **受限 HTTPS 服务**：Rust Axum/axum-server 在用户启用后监听局域网 IPv4，默认端口 1443；只提供已打包的 `/pad/` 静态资源、配对 API、WSS 和无材料的健康检查。API 检查 Host/Origin，网络不暴露 Tauri IPC、文件路径、通用导入或地图编辑能力。客户端只获授权手稿的内容。
2. **设备信任**：Workspace 首次启用生成专用本地 CA，根证书和私钥保存在 `ink-lan/trust/`，目录/私钥使用 0700/0600 权限；服务启动时为当前局域网地址签发叶证书。电脑 UI 只导出公开 `.crt`，用户自行在平板安装并信任。根证书随 Workspace 保留，重启不自动更换，也不静默修改设备信任库。UI 的 SHA-256 指的是导出证书文件的字节摘要。
3. **配对与单写入者**：二维码有效期 120 秒，只能绑定一个设备凭据。凭据由客户端生成并先保存，再发配对请求；相同凭据重试可恢复丢失的配对响应，其他凭据不能重复领取。恢复凭据有效期 30 天，服务端仅存摘要。配对在事务中递增 epoch，电脑切换只读镜像；生成二维码后的等待阶段也暂停电脑编辑，取消后恢复。断线和正常应用退出不撤销租约，重启沿用端口、CA 和凭据；“收回书写权”或“停止平板服务”才显式撤销旧端。
4. **自动保存与背压**：`mathscape-ink-lan-1` 的持久请求绑定 document/session/epoch、稳定 request_id/operation_id、绝对操作序号和前驱操作身份。浏览器先在一个 IndexedDB 事务中保存草稿元数据、历史操作及 outbox，再按顺序发送；电脑在共享 P1 SQLite 事务提交后返回 durable ACK。一次最多一个持久请求等待确认，预览最多约 30 Hz，可丢弃而不进入历史。ACK 丢失沿用原请求重放，不重编号、不重复落笔。
5. **离线与冲突恢复**：Service Worker 仅缓存画板静态资源，配对和同步 API 不入缓存；已缓存的页面可离线刷新，IndexedDB 保存各 session/epoch 的独立恢复记录。本机保存与电脑保存分别显示；存储失败保留画板内容并允许导出/重试，不能显示为已保存。旧 epoch 队列不能自动合入新会话，可导出恢复 JSON，在电脑“导入恢复草稿”中验证后创建独立可编辑手稿，原稿与快照不变。
6. **镜像与快照**：电脑以增量 IPC 获取已保存操作和临时预览，可跟随平板页面，仍能查看历史快照、登记来源证据。预览不是持久证据；电脑保存镜像快照只覆盖已确认的 head，平板保存快照先排空当前 outbox，再固定请求前缀并复用 P2 Artifact/来源链路。

当前实现边界：单条 WSS 消息 16 MiB，单份传输文档和本机待同步队列各 64 MiB；超过上限保留原内容并提供恢复导出，不静默截断。每次镜像拉取最多 128 个操作，预览 3 秒后失效。默认不允许两个不同画板窗口共同写入同一凭据；同一窗口刷新或重连可替换其旧连接。局域网地址改变后应重新开启服务、使用新地址；浏览器存储按 origin 隔离，旧地址的未同步队列须先通过旧页面导出。撤销、删除与垃圾回收仍遵守 §7.5，未在 P3 自动清理草稿。

软件验证已覆盖真实 TLS 证书链、未知 CA 拒绝、单次配对/响应重放、Origin 与会话范围限制、其他窗口拒绝、durable ACK 重放、前驱与异内容冲突、重启恢复、接管/停止撤销，以及独立恢复导入。真实 HTTPS 服务的浏览器用例覆盖自动保存/快照、横竖屏切换、离线刷新及恢复、电脑重启、多个配对/本机恢复记录切换、旧 epoch 导出、本机事务失败后重试；既有 P0/P1/P2 回归也继续执行。Chromium 测试配置中的证书例外只用于测试 fixture，不进入产品，也不能替代设备信任验收。

### P3.1 首次设置平板向导

P3 回归确认：安装 CA 后，局域网桥接的书写、自动同步和恢复体验符合预期；同一 Workspace 重启服务沿用原 CA，不需要重新安装。主要障碍在首次安装：用户需要自行传输 `.crt`、在 Android 设置中找到 CA 安装入口，并判断安装是否生效。P3.1 只降低这一步的操作成本，不改变 P3 的协议、租约、durable ACK 和来源链路。

目标体验：

1. 电脑点击“首次设置平板”，必要时自动开启平板服务，并展示设置二维码。设置二维码与书写配对二维码分离，设置凭据只用于领取公开证书和报告检测结果，不能获得手稿写入权。
2. 平板扫码进入短时 HTTP 引导页。引导页只提供静态说明与公开根证书下载，不提供手稿、Workspace、配对或写入 API；CA 私钥始终留在电脑。
3. 引导页按“下载证书 → 在设置中安装 CA 证书 → 返回本页”展示步骤。优先给出系统设置搜索“CA 证书”的通用路径，并列出 Galaxy 与其他 Android 的菜单路径；尝试打开系统安全设置只作为辅助，失败时使用文字路径。
4. 平板返回引导页后，页面自动通过 HTTPS 探测电脑服务。证书未生效时保持当前步骤；已生效时显示“这台平板已信任当前电脑”，已完成设置的设备可直接跳过安装。
5. 平板进入 HTTPS 检测页，检查安全上下文、IndexedDB 和 Service Worker，并把结果回报电脑。安全上下文与 IndexedDB 通过才视为设置完成；Service Worker 失败时提示离线刷新不可用，不影响自动同步。
6. 电脑实时显示“已打开引导、已下载证书、HTTPS 已信任、检测完成”。完成后提示直接生成书写二维码。

约束：

- 设置凭据随机生成、有效期 15 分钟，服务端只保存摘要；过期、取消、停止平板服务或重新生成时，设置入口立即失效。设置状态只保存在内存，不进入 Workspace。
- HTTP 引导服务只在设置期间监听，默认端口为 HTTPS 端口减 1，占用时使用系统分配端口。它校验 Host，只服务设置页、静态资源和 DER 编码的公开证书。HTTPS 探测仅允许本次设置页 Origin 跨源读取。
- 证书仍需用户在系统设置中确认安装；Android 普通设备不允许网页或普通应用静默安装 CA，产品不承诺一键安装。首次领取证书走 HTTP，因此应在可信网络中设置；引导页说明证书用途及删除位置，不要求关闭系统安全功能。
- 设置成功记录只用于提示，下一次连接仍以实际 HTTPS 访问为准。更换 Workspace 或丢失 CA 后，检测失败并重新进入引导。
- `xiaosalab.com` 作为后续托管说明与 P3.2 免证书入口的域名；P3.1 不依赖互联网，也不把局域网证书托管到外部服务。

实现状态：电脑“平板书写”面板已提供“首次设置平板”、独立设置二维码和四步进度；DesktopService 在设置期间启动受限 HTTP 引导服务，平板引导页下载 DER 公开证书并轮询 HTTPS，HTTPS 检测页回报存储与离线能力。自动化验证覆盖错误凭据、Host/Origin 限制、证书内容、HTTP 服务不提供画板与配对接口、结束设置后失效，以及真实浏览器中的完整引导。

验收：在未安装 CA 的 Tab S8+ 上，仅通过电脑二维码与引导页完成安装和检测；电脑显示检测完成后，扫描书写二维码即可无证书警告地书写。已安装设备重新进入设置时直接显示已信任。过期链接、错误凭据和停止服务后均不能下载证书或报告结果；现有 P3 回归继续通过。

### P3.1.1 设置完成后的书写衔接与写入权状态

P3.1 实机反馈：完成证书引导后，平板停在“设置完成”，用户还要回到电脑重新生成书写二维码；当手稿的写入权仍由之前配对的平板持有时，电脑面板照常显示“生成配对二维码”，点击后直接显示 `ink invariant failed: takeover_required`。原因是平板租约有效期 30 天，电脑重启不撤销写入权；电脑打开该手稿时进入只读镜像，但面板没有按写入权状态调整操作，设置会话也没有绑定手稿。数据层拒绝在平板持有写入权时签发二维码是正确的保护，问题在于产品流程没有给出可选路径。

目标体验：

1. 面板按写入权状态显示操作。写入权在电脑时照常生成书写二维码；写入权在平板时显示“正在由平板书写”、连接状态、最近同步时间和平板报告的待同步数量，主操作为“在这台平板继续”，次操作为“换一台设备书写”，并保留“收回书写权”。
2. “在这台平板继续”展示不含配对凭据的 `/pad/#doc=<document_id>` 地址。平板使用 IndexedDB 中该手稿的连接凭据恢复会话，不转移写入权；本机没有该手稿凭据时提示改用“换一台设备书写”。
3. “换一台设备书写”生成转交二维码。生成时不改变当前持有者，原平板可以继续同步；新设备扫码领取时才在同一事务中撤销旧凭据并转交写入权，并通知原平板连接关闭。原平板已报告待同步操作或当前离线时，电脑先提示建议在原平板同步，确认后才生成二维码；转交后原平板未同步内容保留在本机，可导出恢复草稿。
4. 从手稿打开“首次设置平板”时，设置会话绑定该手稿。平板完成检测后显示“开始书写”，不再扫描第二个二维码：本机持有该手稿有效凭据时直接恢复；写入权在电脑时，电脑完成本机保存后自动签发一次性配对；写入权在其他平板时，电脑面板请求用户确认转交。
5. 原始错误码不直接展示给用户，统一转换为可执行的提示，例如“这份手稿正在由平板书写。可以在平板继续，或转交给新设备。”

约束：

- 设置码经 HTTP 传输，可能被局域网窃听，因此不能换取书写授权。设置二维码另含一次设置会话有效的书写衔接码，放在 URL 的 `#` 之后，浏览器不会发送到网络；平板只在 HTTPS 检测页通过 `/api/setup/handoff` 使用它，服务端只保存摘要。主动篡改 HTTP 引导页的攻击者本就能替换证书，属于首次信任的既有限制，引导页继续展示证书指纹。
- 衔接只返回已有 P3 配对流程使用的一次性配对码，平板仍通过 `/api/pair` 领取连接凭据；配对码保存在内存，有效期不超过五分钟，过期后由电脑按需重新签发。平板到达“开始书写”页后，电脑才签发配对并进入只读等待，避免安装证书期间锁住电脑书写。
- 恢复判定只接受平板通过 HTTPS 提交的、能认证为该手稿当前写入者的凭据；不匹配的凭据不被记录，也不改变写入权。
- 转交二维码只在签发时的写入 epoch 未变化时有效；原平板继续同步的操作属于已确认历史，转交时一并交给新设备。电脑收回写入权或其他设备先完成领取后，旧二维码失效。
- 数据层继续拒绝未声明转交的配对签发；`takeover_required` 只作为内部保护，不再是正常流程的用户可见结果。

实现状态：数据层签发配对增加显式转交参数，领取时按当前写入者决定校验 head；配对成功后通知被替换设备关闭连接。设置会话绑定手稿并增加衔接码、衔接状态与 `/api/setup/handoff`；平板检测页查询本机凭据后自动选择恢复或配对；InkPad 支持 `#doc=` 恢复入口。电脑面板按写入权状态切换操作，提示转交风险并转换错误文字。

验收：在开发 Workspace 中由平板持有写入权的手稿上，电脑面板显示平板书写状态而不是报错；“在这台平板继续”无需配对即可恢复。另一台设备（或另一个浏览器）扫描转交二维码后获得写入权，原平板显示写入权已转移并保留未同步内容。从手稿重新进行“首次设置平板”，检测完成后点击“开始书写”即进入该手稿，无需第二个二维码。HTTP 设置码单独不能换取配对；现有 P3 与 P3.1 回归继续通过。

实机回归记录（2026-10-15）：用户完成本轮验证并确认 P3.1 正常实现；已导入证书的平板可正常进入书写页面，P3.1.1 的验收状态更新为通过。

### P3.2 免证书便捷连接（暂缓）

2026-10-15 调整优先级：现有局域网 HTTPS、持久 CA、首次设置引导与设置后书写衔接已满足当前使用需求，暂缓基于 `xiaosalab.com` 的免证书入口。该扩展不作为 Ink v0 或后续核心工作流的前置条件，现有手写能力进入日常维护与缺陷修复。

后续优先在独立提案中统一系统对象生命周期与删除语义，并围绕具体数学问题推进核心工作流。删除设计承接 §7.5，结合已有地图对象退役与登记撤回能力，统一考虑手稿、快照、材料、来源对象、未来语义对象及历史引用；先明确规则和必要的用户清理能力，再分阶段处理物理清除与 Artifact 垃圾回收。核心工作流复用当前手写采集和证据链，将材料、用户问题、指定手稿快照与后续 Agent 分析衔接起来，具体范围另行收敛。

当首次设置仍显著阻碍实际用户使用，或明确需要跨网络连接时，再评估恢复 P3.2；届时重新确定域名服务、配对与传输方案及运维边界。

依赖关系为 P0 → P1 → P2 → P3。P0 可以使用小型临时 LAN harness 测量设备，正式网络协议与产品服务仍由 P3 交付。多模态输入和 Android 增强分别以 v0 契约为前提，不改变这个来源闭环。

## 13. 验证与验收

### 12.1 自动化验证

| 层 | 必须覆盖的情形 |
| --- | --- |
| Domain / Schema | 非有限数值、越界、非法状态机、缺失能力、错误页/笔迹引用、未知版本 |
| TS / Rust 一致性 | 同一操作 fixture 的可见状态、撤销重做、快照指纹和选择结果一致 |
| Store | 迁移、重开、并发写入、序号缺口、幂等重试、同标识异内容、事务失败 |
| Artifact / Snapshot | payload 损坏、提升失败、登记失败、快照前缀固定、失败后重试 |
| Transport | ACK 丢失、重复发送、网络中断、旧 epoch、超限、背压、无效凭据 |
| Desktop / Reader | 真实 Pool/SQLite 服务测试、重开、历史快照打开、SourceSpan 回链 |
| 兼容 | 既有 PDF/Markdown locator、旧 Workspace、现有来源图与发现工作流 |

故障注入至少覆盖：事务成功前断开、事务成功后 ACK 丢失、payload 已登记但操作未提交、快照 Artifact 已生成但快照回执未提交、服务端重启、客户端刷新、未终结笔迹，以及写入权转移后旧端恢复。

默认测试使用轻量可分发 fixtures，不依赖私人教材、真实模型或物理设备。浏览器自动化验证交互与协议，不能替代真实 WebView 和 S Pen 测试。性能门槛在 P0 明确后作为后续验收依据，不用未经测量的风险消除百分比。

### 12.2 Ink v0 完成标准

1. 从已有习题或自由草稿开启会话，在目标设备连续书写达到 P0 约定门槛；
2. 压感与能力缺失按实测记录，预测与渲染样本不污染采集证据；
3. 擦除、撤销和重做不删除历史，可重建相应可见状态；
4. 支持的进程崩溃场景中，所有已 durable ACK 的操作在重开后存在且不重复；
5. 断网期间本地书写不等待网络，成功写入 outbox 的操作在恢复后有序同步；
6. pending、冲突和存储失败均有明确状态与恢复入口；
7. 快照请求绑定固定前缀，重复请求返回同一回执，后续编辑不改变旧内容；
8. 从 Ink SourceSpan 能打开正确快照和选定笔迹，关联材料可回溯到指定修订；
9. 来源登记失败不会被展示为成功，也不破坏已保存手稿；
10. 已有 Workspace 可升级，旧 PDF/Markdown 定位与相关回归通过；
11. LAN 正式使用的传输信任、恢复认证与单写入者边界经真实设备验证；
12. 首个端到端场景、设备矩阵、性能结果和故障恢复证据进入验收记录。

## 14. 技术选择与后续接口

第一版采用 Pointer Events + Canvas 2D + 可替换的 perfect-freehand 渲染适配；真正的存储模型属于 Mathscape。使用实测压感时关闭渲染器的模拟压力，保存笔刷与渲染配置以支持回放。

Android 高质量输入候选为 Tauri Kotlin 插件与 AndroidX Ink。原生端负责本地渲染和缓冲，批量输出统一 Ink 操作；不逐点在 Kotlin、Rust 和 JS 之间往返。原生笔刷或网格不能成为唯一来源格式，基础样本必须仍能被 Mathscape 读取。

未来分析输入包至少绑定 snapshot_artifact_id、selection、context_revisions、user_intent、render_artifact/config 与处理预算。分析结果保存 run、输入指纹、版本和证据，不回写原始 Ink。LLM 图片消息、供应商能力、受管图片解析、成本与取消另行实施。

参考能力来源：

- [Pointer Events 规范](https://www.w3.org/TR/pointerevents3/)：采样、默认属性、coalesced/predicted events 与安全上下文；
- [perfect-freehand](https://github.com/steveruizok/perfect-freehand)：笔迹轮廓与实际/模拟压力配置；
- [Tauri 移动插件](https://v2.tauri.app/develop/plugins/develop-mobile/)：原生 Kotlin 适配边界；
- [AndroidX Ink](https://developer.android.com/jetpack/androidx/releases/ink)：后续原生采集与低延迟渲染候选。
- [Axum WebSocket](https://docs.rs/axum/latest/axum/extract/struct.WebSocketUpgrade.html)、[axum-server RustlsConfig](https://docs.rs/axum-server/latest/axum_server/tls_rustls/struct.RustlsConfig.html) 与 [rcgen](https://docs.rs/rcgen/0.14.10/rcgen/struct.CertificateParams.html)：P3 HTTPS/WSS 服务和证书签发能力，版本以 Cargo.lock 为准。

## 15. 实施前需收敛的决定与文档维护

P0 收敛数值编码、批次大小、性能门槛、基础笔刷以及 Ink locator 的粒度规则；P3 收敛局域网传输与设备信任方案。这些决定必须由 fixture 或实测支撑并更新本提案，不能以“后续再说”绕过对应阶段验收。

物理表结构、函数签名、Schema 与协议资源在实现中冻结；数据库迁移顺序追加，不预占当前仓库的迁移序号。实现后按已交付能力更新四份工程主文档，提案继续区分已完成任务和后续扩展。

本次提案不修改手写生态调研、不替换现有来源发现提案，也不要求先实现 EMIR 全部语义层。Ink v0 的长期边界是忠实记录、可靠恢复、不可变快照与可验证来源定位。
