# 核心工作流与 Agent 执行层设计笔记

状态：探索草案。本文记录候选架构和验证方向，不是实施契约。后续模型与基础设施设计见[扩展草案](core-workflow-foundations-extension-v0.1.md)。

## 目标与职责

核心工作流包含两种互通的使用方式：围绕长期问题维护可随学习反馈调整的路线，以及从具体困惑出发，结合阅读选区和手稿进行调查、解释与练习。路线中的节点可以触发局部调查；调查得到的证据可以提出路线修订。

由 Mathscape 管理用户目标、材料版本、用户反馈、路线和地图变更验收。执行适配器以可替换的方式调用完整 Agent：可先用 [Humanize（hmz）](https://docs.humanfia.ai/humanize/) 验证角色编排、审查和暂停恢复，再与直接接入 [Codex App Server](https://developers.openai.com/codex/app-server/) 或 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 比较。不直接采用面向软件开发的默认审查循环，也不要求自行实现底层 Agent 循环。

## 单轮调查

1. 任务契约绑定目标、来源版本、选区、手稿、可用工具、预算和验收条件。可修改的执行计划（如 `plan.md`）与契约分开；调查记录保留来源、失败尝试及待回答问题。
2. Agent 可以检索来源、查询地图、尝试数学检查，返回带来源的解释、练习或候选图变更。执行环境只暴露所需材料；Agent 不直接写入正式地图，候选须经过相应检查和用户审核。
3. 需要真实反馈时暂停调查并保存待回答问题。用户作答、自评、工具检查和 Agent 诊断分别记录；默认回复或审查意见不得冒充用户反馈。恢复时依据 Mathscape 持久化的上下文和累计预算，重试提交不得重复写入。

## Lean 与验证切片

先验证一条可暂停、恢复的局部调查：从选区和手稿出发，用固定版本的 Lean/mathlib 环境检查前提和局部目标，生成解释与图提案，再根据真实用户反馈更新调查。检索命中只是候选；局部形式检查不等于用户已经理解，也不能自动证明未形式化的自然语言论证。涉及 R/D/T/X 的证明分解时，应保留子目标之间共享的约束，而不是假设每个子目标独立。

比较执行后端时保持任务、模型和预算可比。优先验证反馈来源、续跑后的上下文、提交的幂等性、来源变更后的重新检查，以及练习能否揭示用户对方法的掌握。
