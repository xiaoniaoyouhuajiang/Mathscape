# Mathscape 数学地图入门：先用白话理解 EMIR 和 R/D/T/X

这份文件给第一次接触 Mathscape 数学地图的 Agent 读。它只解释“这些东西在软件里要解决什么问题”，不替代正式准则。遇到规则冲突，回到 `reference-index.md` 指向的正式版本。

## 1. Mathscape 到底在保存什么

Mathscape 要同时回答两个问题：

1. **原文在哪里？** 例如一本书第 3 页的某个定义、一段 PDF 公式，或者用户手稿中的一组笔迹。
2. **这段内容在数学上是什么意思？** 它有哪些前提，怎样推导，能否和别的书或形式化定理联系起来。

第一个问题属于**来源层**。这里保存 Artifact、SourceSpan、SourceSemanticUnit 和精确的 `content_ref`。来源层的内容必须能回到原文或手稿，不能因为 Agent 做了总结就丢掉原始位置。

第二个问题属于**语义和工作网**。这里保存对象卡、方言约定、表示、证明状态、推理边、运输边、债务和证据。它们是候选解释，除非经过用户接受和相应审查，不会自动变成可信知识。

## 2. EMIR 用一句话怎么理解

EMIR 是 **Experimental Mathematical Intermediate Representation**，即“实验性数学中间表示”。可以把它理解成数学地图的中间层：

- 它把“这段文字来自哪里”和“我们认为它表达什么”分开；
- 它允许同一数学内容在不同书里有不同说法；
- 它允许先保存不完整、未上下文化或有争议的候选；
- 它要求每个候选都能回到来源、版本和证据。

EMIR 不是一个自动认证器，也不要求所有内容先形式化。一个 Lean 定理通过，只说明那份 Lean 源码在指定 profile 中成立，不说明它一定忠实翻译了书上的话。

可以用下面的链条理解成熟度：

```text
原始 Artifact
  → 找到可定位的片段
  → 登记来源单元
  → 补充方言和上下文
  → 候选语义对齐
  → 形式化或 R/D/T/X 工作网
```

后面的对象必须保留对前面对象的引用；前面的对象不需要伪造后面的字段。

## 3. R/D/T/X 是四种不同动作

不要把 R、D、T、X 当成四种普通节点名称。它们描述的是一条数学路线中发生的不同动作。

- **R（Representation，表示）**：当前用什么方式看问题，以及这种方式允许哪些对象和算子。比如“矩阵的奇异值表示”“概率分布表示”“对偶空间表示”。
- **D（Derivation，表示内推理）**：在同一个表示里，根据已经登记的前提、定义、引理和守卫得到下一步。例如在谱表示中对每个特征值逐项计算。
- **T（Transport，表示运输）**：从一种表示换到另一种表示，而且需要独立的保持或重建证书。比如把一个参数动力学问题换成核函数问题，或者把级数换成概率分布来处理。
- **X（Expansion/Compression，展开或宏）**：把一组重复的定义展开、见证、切分或桥接步骤压缩成一个可展开的接口。X 不能藏起关键假设，也不能把真正需要证明的 T 假装成宏。

小黄的 `rdtx_try.md` 中有几个容易理解的例子：

- **T04 伪逆 / 谱滤波**：伪逆、截断 SVD、岭回归和梯度流都可以看成“对奇异值套一个函数”；这里的谱表示是 R，不同表示之间的转换才可能是 T。
- **T08 Laplace 原理**：很多项的和在极限中由最大项附近支配；“只看最大项附近”可以作为一个 X，但需要水平集、尾部估计和测度条件等证据。
- **T12 KL / Donsker–Varadhan**：把一个难算的原问题换成变分问题，是一种对偶表示运输；前提和失败见证必须单独记录。
- **T18 Hahn–Banach / Riesz**：先把逼近问题运输到对偶函数，再用测度或 Fourier 唯一性处理；这不是“原文写了一个 proves 边”就自动成立的证明证书。

## 4. Debt、guard 和 lemma 的区别

这三个词不要混用：

- **guard（守卫）**：说明当前属于哪个分支。例如“矩有限”或“参数为正”。去掉 guard 往往表示进入了另一个情形。
- **Debt（未偿还义务）**：当前路线确实依赖、但还需要单独核对或证明的条件。它要写明分支、量词、消费者和失败方式。
- **lemma（派生引理）**：由已经登记的定义、Debt 和 guard 推出的中间事实。它不是新的假设。

Debt 还要说明去掉后坏在哪里：

- theorem-Debt：定理结论真的失败；
- statement-Debt：原陈述变得不适用；
- route-Debt：只是这条证明路线走不通，换路线可能仍然成立。

## 5. 什么叫一条“合格路线”

一张 work-net 不是画得越复杂越好。它需要：

1. 对象卡中的每个分支都能在网里找到对应结论；
2. 每条核心边的前提都被显式列出；
3. 真正的表示切换有 T 和重建证书；
4. 每条核心边都有自己的证据端点；
5. 失败、未决和部分证据保持为可见状态。

I1–I7 是检查这些问题的准则，不是“认证章”。`pass`、`fail` 和 `undecidable_under_current_criteria` 都是给用户审查的结果，Agent 不能借此自行宣布数学正确。

## 6. 看到一个对象时，先问四句话

1. 这是谁在什么来源里说的？
2. 这句话的完整前提和分支是什么？
3. 当前路线是在同一种表示里推理，还是换了表示？
4. 我能把这一步准确回链到哪一段原文、手稿或形式证书？

如果其中一个问题答不上来，保留候选或标记待核，不要用模型猜测补齐。
