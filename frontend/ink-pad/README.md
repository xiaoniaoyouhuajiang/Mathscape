# Mathscape InkPad（P3）

InkPad 是正式的局域网平板入口。手稿保存到正在运行的 Mathscape Workspace，不再依赖 P0 的 Node 文件接收后台。P3 与 P3.1（含 P3.1.1 设置完成后直接进入手稿、继续原平板和转交新设备）已完成用户实机回归。P3.2 免证书便捷连接暂缓，当前能力进入日常维护。

## 开始书写

在 `mathscape/` 启动同一开发 Workspace：

```sh
npm --prefix frontend run tauri:dev:local_1
```

1. 在 Mathscape 点击“手写”，新建或打开当前可编辑手稿，然后打开“平板书写”。
2. 点击“开启服务”。默认端口 1443；电脑和平板须在同一局域网，系统防火墙须允许此端口。
3. 首次使用这台平板时，点击“首次设置平板”并用平板扫描设置二维码。平板会引导下载公开证书、在“设置”中安装为 CA 证书并自动检测；电脑同步显示每一步进度。设置链接 15 分钟有效，只提供公开证书与检测，不能书写或读取手稿。检测完成后平板显示“开始书写”，点击即进入发起设置的手稿，电脑自动保存并切换为只读镜像，不需要再扫书写二维码。该步骤每个 Workspace/设备通常只需做一次；也可以用“手动导出证书”自行安装。首次领取证书走局域网 HTTP，请在可信网络中设置。
4. 点击“生成配对二维码”，在“电脑地址”选择平板能访问的局域网 IPv4 地址，扫码或复制链接访问。`127.0.0.1` 仅供电脑本机测试。二维码两分钟有效，只能绑定一个设备凭据。
5. 确认浏览器访问 HTTPS 没有证书警告，页面显示“电脑已连接 · 自动同步”。设置向导已检测安全上下文、IndexedDB 和离线缓存；忽略证书警告不算完成设备信任。
6. 直接书写，电脑自动保存完整操作并显示只读镜像。无需点击“保存到电脑”。“本机已保存 · 待同步 N 个操作”与“电脑已保存至 head N”分别表示设备存储和电脑确认。

已设置的平板省略第 3 步，直接从第 4 步开始。

如果手稿之前已交给平板，平板会一直持有书写权（电脑重启后也保留，最长 30 天），“平板书写”面板会显示“这份手稿正在由平板书写”及连接与待同步状态：

- “在这台平板继续”给出不含凭据的 `/pad/#doc=` 地址，原平板打开即用本机凭据恢复，不转移书写权。也可以直接在原平板画板点“重试连接”。
- “换一台设备书写”生成转交二维码。新设备扫码前原平板照常书写同步；扫码后原平板显示写入权已转移。原平板离线或仍有待同步操作时，电脑会先提示。
- “收回书写权”让电脑立即接管。

从这类手稿发起“首次设置平板”时，原平板完成检测后直接继续；其他平板需要在电脑上点击“转交给这台平板”后才能开始书写。

配对后电脑暂停编辑该手稿，可跟随平板当前页；平板保留笔、套索、变换、整笔/局部擦除、撤销重做、颜色、笔宽、多页和缩放。电脑保存镜像快照只覆盖已确认内容，临时预览不进入快照。

## P3.1 设置验收

1. 从未安装证书的平板扫描设置二维码，只按平板页面提示完成安装；确认返回后自动检测到信任。
2. 确认电脑依次显示“已打开、已下载、已信任、检测完成”，然后生成书写二维码并无证书警告地开始书写。
3. 已完成设置的平板再次扫码，应直接显示已信任；结束设置或超时后，旧设置链接应失效。

## P3.1.1 衔接验收

1. 打开一份写入权仍在平板的手稿，打开“平板书写”：应显示平板书写状态，不再出现 `takeover_required`。
2. 点“在这台平板继续”，用原平板扫码：直接连接并继续书写，写入 epoch 不变。
3. 点“首次设置平板”，用原平板扫码走完检测，点“开始书写”：直接回到该手稿，电脑第五步“平板已进入手稿”打勾。
4. 对电脑可编辑的手稿进行设置：检测完成前电脑仍可编辑；平板进入“开始书写”页后电脑自动切换为只读镜像，点击后即可书写。
5. 用另一个浏览器或设备扫描“换一台设备书写”的二维码：新设备获得完整已同步内容，原平板显示写入权已转移并保留未同步内容。

## 快照、恢复与接管

- 平板“保存快照”先同步当前队列，再使用 P2 的固定前缀快照。电脑历史快照可只读打开、选择并登记证据；继续编辑不会改变旧证据。
- 断网时可继续写，成功保存到 IndexedDB 的操作在网络恢复后自动补传；已缓存画板支持离线刷新。不要清除站点数据或使用会自动清理存储的模式保存唯一副本。
- 正常退出和重新打开 Mathscape 会恢复已启用服务；端口和地址不变时，原设备恢复认证，无需再次扫码。电脑退出期间的新笔迹先留在平板。
- “收回书写权”让电脑接管；“停止平板服务”撤销配对凭据。旧端的未同步队列仍保留，但不能写入新 epoch，页面会明确显示会话失效。
- 在旧端“导出恢复草稿”，将 JSON 传回电脑，再用手稿列表上的“导入恢复草稿”创建独立可编辑手稿。原稿、旧快照和证据不会被覆盖。PNG 仅导出当前页可见内容，恢复 JSON 包含所有页面和操作历史。
- 本机事务失败时显示“未保存”并暂停新书写，内容仍在画板内；先导出恢复草稿，再重试“立即同步”。未显示本机成功保存的内容不能承诺刷新或强制关闭后恢复。

局域网地址改变时，应重新开启服务以签发当前地址的叶证书并生成新链接。浏览器存储按 origin 隔离，新地址无法读取旧地址的队列；迁移前从旧页面导出恢复 JSON。CA 随 Workspace 保留，不要通过删除开发数据库或信任目录解决连接问题。

## 验收流程

1. 扫码后连续书写 20 分钟，回归套索预览、局部擦除、多页、颜色、撤销；不点击同步，确认电脑镜像和已保存 head 持续推进。
2. 断开平板网络，继续写几笔，确认本机已保存且 pending 增加；刷新已缓存页面，确认内容仍存在；恢复网络后 pending 清零且无重复笔迹。
3. 保持平板打开，关闭再启动 Mathscape，确认原凭据、手稿和自动同步恢复。
4. 平板断网写几笔，电脑收回书写权；恢复网络后确认旧端队列保留且不能误写到新会话，导出并导入独立恢复手稿。
5. 平板保存快照，电脑选择并登记来源证据；继续擦改当前手稿，再从地图及重启后的地图打开原快照选区。

设备信任、离线存储和 S Pen 质量验证通过后，记录设备/浏览器版本与结果，再确认 P3 PASS。删除语义另行统一设计，本阶段不自动删除临时草稿。

## 工程验证

在 `mathscape/` 运行：

```sh
npm --prefix frontend run pad:build
cargo test -p mathscape-desktop --test ink_lan
npm --prefix frontend run test:pad-browser
```

Rust 用真实 TLS 验证未知 CA 拒绝、受信任证书链、配对/授权、持久重放、重启/接管和恢复导入。浏览器测试用真实 Rust HTTP/HTTPS 服务和独立 Workspace，覆盖首次设置向导及设置后直接继续/接手、`#doc=` 恢复和转交二维码、自动同步/快照、横竖屏切换、离线刷新、重启、多手稿配对与恢复记录切换、旧队列恢复和本机事务失败。测试证书例外仅用于 Chromium fixture，不进入产品或替代实机验收。

静态资源由 Vite 构建至 `dist-inkpad/`，随后由 Rust build script 嵌入；修改平板页面后需重编 Rust。测试端口 1453，测试数据在忽略目录 `.test-runs/ink-lan-browser/`，不会操作开发 Workspace。

当前限额为单条持久消息 16 MiB、单份传输文档和本机待同步队列各 64 MiB；超限保留原内容并提示恢复导出，不静默截断。协议与实现参见 [P3 提案](../../docs/proposals/handwriting-input-infrastructure-v1.md)、[LAN 服务](../../apps/mathscape-desktop/src/ink_lan.rs) 和 [IndexedDB 存储](../src/ink/pad-store.ts)。
